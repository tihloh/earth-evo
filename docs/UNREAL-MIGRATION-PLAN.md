# Earth Evo — Unreal Engine 5 Desktop Migration Plan

**Status:** Architecture proposal, 2026-10-17. **No Unreal Engine migration has been implemented yet.**

**Source prototype:** [tihloh/earth-evo](https://github.com/tihloh/earth-evo), `main`, v0.8.1 (Three.js browser prototype). Keep it working while creating the Unreal version.

## Product goals and boundaries

Create a **Windows-first desktop planet evolution sandbox**, with continuous globe-to-ground exploration, physically meaningful scale, era-specific geography/ecology, observable wildlife, realistic-looking ecosystems, settlement growth, and interactive god powers.

Foundational rule: **one authoritative geography + simulation state**. Orbital globe tiles, mountain horizons, ground geometry, biomes, water, organisms and settlements must sample the same world coordinates, historical time, deterministic seed and saved edits.

Do not promise literal infinite detail, full scientific accuracy, genuine consciousness, or automatic photorealism. Fidelity increases in deliberate, measurable milestones.

### Default choices pending review

- Use a supported **UE5 stable release** verified with all required plugins, then pin the minor version for reproducible builds. C++ owns world simulation and deterministic algorithms; Blueprints/Data Assets own authoring and iteration.
- **Separate repository proposed:** `tihloh/earth-evo-ue5`. Keep the web prototype as reference and regression oracle. Do not replace/delete the existing `earth-evo` project. Share data schemas and golden sample fixtures, not renderer code.
- **Initial planet mode:** fictional seeded evolutionary planet, improving the existing simulator's procedural rules. Modern authentic Earth and reconstructive paleogeography are **later optional datasets/modes**; Cesium's modern datasets cannot automatically represent prehistoric continents or a changing synthetic world.
- Use **metric physical units:** 1 Unreal unit = 1 cm, elevations in meters, globe ellipsoid/planet radius in meters, creature assets in corresponding meters. Default present-day reference planet: WGS84-like geodetic globe (Earth mean radius ~6,371 km). Never extend the web prototype's artificial `0.018 degrees per local unit` scale into UE.
- No cloud service required for the first desktop playable slice; local saves must work offline.

## Core architecture

```text
World Simulation (C++; authoritative seed + time + state)
  |-- Planet Geometry & GeoCoordinates (ECEF/geodetic / local ENU)
  |-- Geology & Ocean Basin / Historical Geography
  |-- Climate / Hydrology / Biomes
  |-- Species & Evolution / Populations / Local Agent State
  |-- Settlements / Technology / Civ Progress
  |-- Event Log & Save Deltas keyed by spatial tile and epoch
  |
  +-- Planet Renderer: coarse cube-sphere/quadtree tiles (orbit scale)
  +-- Distant Renderer: terrain tiles/HLODs, coastlines, mountains
  +-- Local Renderer: fine terrain, PCG ecosystems, Water, creatures
  +-- God Mode & Timeline UI: write to same world state
```

### Planet/terrain subsystem

- Build a **cube-sphere quadtree or equivalent spherical tile hierarchy** with screen-space-error based LOD, cross-tile skirts/morphing, parent fallback until children load, view-frustum/horizon culling, worker/task-based mesh generation and hard memory budgets. Cube-sphere avoids equirectangular pole distortion. This is **custom planet code**, not ordinary World Partition by itself.
- Use geographic doubles / geocentric coordinates for the complete planet. Move active physics/gameplay into a **local East-North-Up tangent frame** near the player and rebase as needed; test near poles, ±180-degree meridian and elevations.
- The same geographic sampling path generates orbit-height tiles, distant mountains, beaches, exact terrain contact and low-level collision. Globe/ground alignment must not depend on blending two unrelated maps.
- Start with **one 5 x 5 km playable regional area**, still generated by planet coordinates, then allow traversal across tile boundaries and repeated globe descents.
- World Partition and its HLOD tools are useful for detailed **regional static content and settlement/city assets**. Unreal's standard flat grid should not be treated as a complete rotating/spherical planet engine.
- Nanite for appropriate authored static rocks, cliffs, mountains/buildings. Do not assume every runtime-generated terrain mesh can use Nanite automatically.

### Accurate geography and time

- First milestone: deterministic synthetic geography with convincing mountain ranges, valleys, ridges, canyons, volcanoes, beaches, connected lakes, rivers, estuaries and watersheds.
- Establish **height in meters**, slope, temperature, rainfall, substrate, biome, drainage direction, flow accumulation, erosion state, coast distance and ocean depth as world data. Rivers should flow downhill through consistent drainage networks; volcanoes are kilometer-scale landforms, not independent props.
- Later choose one or both **authentic Earth datasets** (licensed height/bathymetry, coastlines) and **time-indexed plate/continent reconstructions**. Validate data provenance, year availability, interpolation and geography changes; do not overlay current Cesium imagery on prehistoric seas.
- Cesium for Unreal is **optional** for georeferencing, modern real-Earth reference mode or modern datasets (including local 3D Tiles). Do **not** make Cesium ion connectivity a requirement for a self-contained fictional procedural planet.

### Biomes, weather and water

- Use Unreal **PCG** for slope/altitude/latitude/temperature/moisture/soil/time-driven ecological placement; deterministic per-tile seeds, Poisson/blue-noise spacing and species density constraints. Maintain a separate data-driven species/plant database.
- Ocean should be a continuous spherical sea-level surface with large-scale wave spectrum and close-up shoreline foam; regional rivers and lakes can integrate Unreal's Water System. Water material, buoyancy, water depth and habitat mask must share their geography. Use Niagara sparingly for spray/rain/snow.
- Lighting: Sky Atmosphere, Volumetric Clouds, time-of-day sun, scalable Lumen and reflections, distance/quality presets. Include real performance budgets for reflection and weather.
- **No fog of war** as a rendering shortcut. Distant geography should stay visible with reduced mesh detail and physically motivated atmospheric fading.

### Wildlife, behavior and civilization

- Keep a **hierarchical simulation**: low-frequency planetary ecology/settlement aggregates off-screen; deterministic regional populations; individual full agents only close to the camera. Unloading graphics must not delete world history.
- Species/habitat matching: broad geological epoch/fossil window; deep connected marine water vs lakes, vegetation/food webs, climate zone, predators/prey and migration corridors. Require data-driven species validation before spawning.
- Unreal **MassEntity** for large groups, LOD representations and spatial updates; **StateTree** for individual actions (forage, stalk, flee, hunt, rest, breed, build, trade), with NavMesh, movement strategies and animation states. High-fidelity visible animals should use distinct skeletal rigs, correct anatomy, IK and authored animation; no shared dog skeleton for whales, birds, humans and dinosaurs.
- Start with **three representative animals** (one herbivore, one predator, one aquatic organism), one early human, and a small historically plausible shelter/camp. Expand species families **after** habitat correctness, locomotion and save persistence pass.
- Settlements evolve from shelters to hamlets to larger infrastructure via resources, terrain, era, tools, food, population and travel routes. Persist decisions/structures; no spontaneous modern cities in an early epoch.

### Simulation, time travel and persistence

- Port **algorithms and data contracts**, not Three.js objects: `src/simulation.js` seeded global ecology/timeline; `src/geography.js` deterministic geographic sampling; `src/surface-world.js` agent state; `src/era-ecology.js` species/habitat data; `src/open-world.js` stream/cache strategies.
- Replace current 1600-step illustrative eras with a **versioned physical time representation**: years before present, absolute geologic time, historical calendar and hypothetical future. Epoch definitions are Data Assets, not labels hard-coded in rendering.
- Use deterministic world seed and stable spatial tile IDs. Save **only edits, changes, identities, populations, structures, and simulation checkpoints**; reconstruct unchanged world tiles from seed/data version. Never lose edited settlements merely because a distant cache evicts them.
- Use a checkpoint/event-log policy for rewind. Distinguish reversible simulation state from visual timeline interpolation; time travel is not achieved simply by rebuilding vegetation for an era.
- Add save version and upgrade code. Existing web JSON can initially import seed, coordinates, timeline and selected known values; promise full save compatibility only after explicit mapping tests.

## Existing prototype → UE5 mapping

| Prototype files | Target responsibility | Approach |
| --- | --- | --- |
| `src/geography.js`, `src/physical-features.js` | `EarthGeo` / `EarthTerrain` C++ | Reimplement geospatial math; compare golden reference fixtures |
| `src/simulation.js` | `EarthCore` / `EarthTimeline` | Reimplement clock, RNG, populations and event log |
| `src/surface-world.js`, `src/era-ecology.js` | `EarthLife` | Preserve species data, migrate behavior to StateTree/Mass |
| `src/open-world.js`, `src/terrain-lod.js` | `EarthStreaming` | Build global quadtrees + local chunk streaming and budgets |
| `src/renderer.js`, `src/surface-view.js` | `EarthView` | Replace entirely with UE5 rendering/materials/assets |
| `src/creature-models.js`, `src/vegetation-view.js` | `EarthAssets`, PCG | Replace procedural primitives with authored/instanced art |
| `src/app.js`, `src/zoom-continuum.js` | `EarthPlayerController` and UMG | New camera logic/UI; preserve controls and behavior |

Controls invariant: **left mouse pan, right mouse rotate, wheel zoom**. Near-zero inertia by default; configurable 0/2/5% glide. Zoom should work from orbit through intermediate scales to eye level and back without black frames, invalid coordinates, or camera teleport.

## Milestones and acceptance gates

### Phase 0 — feasibility/technical spike (1–2 weeks)

- Create a separate C++ UE5 desktop project, pin engine/plugin versions, source control/Git LFS and storage rules.
- Benchmark Epic default open-world map on development PC (record hardware/GPU/RAM and baseline FPS).
- Prototype a **round planet with one generated island/mountain region**, real metric geodetic transforms, one orbit camera and one local ground camera.
- **Gate:** stable 10-minute orbit→ground→orbit loop; correct location, no scale jumps, terrain loads without visible missing tiles; executable Windows build.

### Phase 1 — one planet/geography source (3–5 weeks)

- Deterministic height/depth generator, cube-sphere tile IDs, 3–5 LOD levels, streaming task scheduler, cache/persistence identifiers, strict coast and terrain stitching.
- Separate surface curvature math from visuals; implement origin rebasing and collision.
- **Gate:** repeated zoom to same lat/lon returns identical altitude/water mask; no cracks along LOD and tile boundaries, dateline or polar edges; distant mountain silhouette stable.

### Phase 2 — environment vertical slice (3–5 weeks)

- One representative region with mountain, valley, river→lake→sea connection, beach, planted biome, day/night and basic weather.
- PCG foliage/terrain assets by data-driven climate and era. Ocean and regional water visuals; lightweight reflections and shoreline foam.
- **Gate:** plausible water levels and terrain transitions, no inland ocean whales, no floating forests, controllable render distance; performance target established on reference hardware.

### Phase 3 — first living world (4–7 weeks)

- Port timeline and ecology domain state; implement three habitat-matched animal types, one human, inspect/follow, hunger/thirst/fleeing/hunting, mating and early shelter construction.
- Skeletal animation rigs and simple vegetation life cycle. Planet/regional changes persist and feed appropriate aggregate world state.
- **Gate:** behaviors visibly correspond to needs and biome; no anachronistic animal; travel/unload/revisit and save/load preserve entities and settlements.

### Phase 4 — timeline, god mode, historical stages (4–8 weeks)

- Evolving environments, data-driven epoch transitions, event log/checkpoints, climate/sea-level and habitat changes; god interventions at local/planet scale.
- First time-appropriate settlements, harvesting/building and chronology-aware clothing/structures.
- **Gate:** rewind/advance deterministic from same seed+events and plausible state transitions; long-running save/reload stable.

### Phase 5 — realistic asset/performance expansion (ongoing, months)

- Expand biomes/species/settlements, anatomical motion, sound, weather, geology and environmental complexity.
- Optional sourced modern Earth/paleogeography mode, offline dataset packaging, cinematic fidelity presets.
- Regression suite includes FPS/frame pacing, memory/VRAM budgets, tile streaming under fast flight, 1-hour simulation soak and low/medium/high GPU settings.

**Timing note:** All phase durations are rough experienced-developer planning ranges with suitable assets/hardware. A solo developer new to Unreal or producing original AAA-quality assets should budget substantially longer. Prototype vertical slice could take ~2–4 months; polished full vision is multi-year.

## Performance targets (starting targets, not measured)

- Windows desktop target: **60 FPS at 1080p** on a nominated mid/high range DirectX 12 GPU; configurable 30/60 and low/medium/high presets.
- Aim for **<=16.7 ms average frame time** at 60 FPS and minimize >100 ms streaming hitches; benchmark the actual target machine.
- Memory budgets per active tile tier, capped procedural tasks per frame, cancellation when moving quickly, async generation, pooled components and instancing.
- World remains simulated at appropriate aggregate granularity, rather than billions of skeletal Actors.
- UE5 development machine: Epic documentation recommends Windows 11, **32 GB RAM** and **8 GB+ graphics VRAM**. Verify actual user hardware before committing to high-end lighting defaults.

## First development sprint (concrete tickets)

1. Establish `earth-evo-ue5` project, `Source/EarthEvo/` modules, Git LFS, ignore derived assets, initial Windows packaged smoke build.
2. Add geodetic/ECEF/local-ENU C++ conversion with tests; set scale in meters/centimeters.
3. Implement `FWorldSeed`, `FWorldEpoch`, `FGeoTileId`, `FHeightSample` and `FWorldSaveHeader` plus JSON golden fixtures generated from current JS prototype.
4. Render seed-derived spherical quadtree base with at least two height LODs and one floating-origin local ground zone.
5. Build mouse controller (left-pan/right-orbit/wheel) and continuous orbit-to-ground fly/zoom; instrument camera altitude and tile IDs.
6. Capture metrics and test results: 10-minute zoom loop, same-coordinate comparison, missing tile count, FPS, load time and memory.

**Do not start by importing every animal model or building cities.** First prove one correct planet/terrain/camera and a persistent, physically scaled regional island.

## Technical risks and decisions to resolve before phase 2

1. **Planet identity:** Synthetic evolving planet or authentic Earth (today + historical reconstructions)? Different data/licensing cost and validation implications.
2. **Runtime terrain format:** Custom procedural mesh/cube-sphere vs transformed 3D Tiles; compare one-zone prototypes. Cesium is optional; default fictional mode must be offline.
3. **Coordinate precision and world curvature:** Planet-scale doubles plus local physics frames; all subsystems must honor origin changes.
4. **Historical credibility:** Scientific dataset sources/rights, epoch timing and model uncertainty. Avoid presenting approximations as exact.
5. **Licensing/assets:** Unreal Engine game royalties generally start after $1M lifetime gross attributable product revenue; asset marketplace and Cesium datasets have separate licenses/possible cloud costs. Review intended distribution.
6. **Repository size:** Unreal binary `.uasset`/large textures/meshes need Git LFS or Perforce; avoid committing caches and generated builds.
7. **Risky features:** Large World Coordinates, experimental PCG extensions and Cesium integration require version-specific validation; do not make all subsystems experimental simultaneously.
